Surround-View Bird's-Eye View and Lane Detection in C++11

Personal project (private repository)
C++11ONNXYOLOPFisheye camera modelCANPython

Problem

Go from a raw surround-view vehicle recording to lane positions relative to the car, using only plain C++11 and no external libraries, so it builds even on an old MinGW toolchain.

What I did

  • Reverse-engineered the recording format: frame layout of four 640×400 grey camera images, embedded CAN-bus messages, and a right camera stored rotated 180°; built tools that summarize recordings, extract frames and export CAN logs.
  • Implemented the fisheye camera model (polynomial distortion, mount tilt/yaw/roll) with forward projection and inverse back-projection to the ground plane; the camera → road → camera round trip is exact.
  • Built a lookup-table stitcher that combines the four cameras into a 400×640 bird's-eye view at 25.65 mm per pixel, with per-camera regions and feathered seams.
  • Wrote a self-contained ONNX inference engine (model-file parser and about 26 operators including Conv, BatchNorm, Resize and NonMaxSuppression) to run a YOLOP lane and drivable-area model; its boxes, classes and lane mask match ONNX Runtime exactly.
  • Converted lane pixels to vehicle coordinates and reported the lateral distance from the rear-axle midpoint to the nearest left and right lane lines and the lane width, per frame, in a CSV summary.
  • Added a point-conversion tool (top-view pixel ↔ world ↔ rear axle ↔ raw camera pixel) and a GIF demo generator, with Makefile and Windows build scripts.

Result

C++ results match the reference implementations exactly (bird's-eye view: zero pixel difference; network: identical detections and lane mask). Example frame: lane lines 1.45 m left and 2.17 m right of the rear axle, lane width ≈ 3.6 m.
